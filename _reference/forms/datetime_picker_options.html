Planned Start — Date/Time Picker Options

Same field, three different widgets. All loaded via CDN <script> tags — no build step, same pattern this app already uses for Bootstrap/DataTables/jQuery.

Current — Native datetime-local baseline
—
  • Zero dependencies, already in place.
  • Rendering is 100% controlled by the OS/browser — Chrome, Safari, Firefox and mobile all look different, and you can't restyle the calendar/clock popup at all.
  • No way to enforce business rules (e.g. block past dates, 30-min steps) without extra JS anyway.
Option A — Flatpickr recommended
—
  • Single calendar + inline time spinner, one consistent look on every browser/OS.
  • ~15KB, no other dependency, easy to theme with plain CSS variables to match AdminLTE's palette.
  • Built-in support for min/max dates, disabled dates, 15/30-min step, and a "confirm" button pattern — useful for "Planned Start can't be before Requested Date" type rules later.
Option B — Tempus Dominus most "Bootstrap-native"
—
  • Built specifically for Bootstrap 5 — tabs between calendar/clock views, icons and spacing already match Bootstrap components exactly (it's the spiritual successor to the classic AdminLTE 2/3 datetimepicker).
  • Heavier: needs Popper.js as a second dependency (already implied by Bootstrap's own JS bundle, so effectively free here).
  • More configuration surface (locales, view modes, restrictions) if the form grows more date-heavy later.
My take: Flatpickr is the easiest win — smallest footprint, easiest to restyle to match the app's colours exactly, and covers everything the work order form needs (min-date validation, step intervals). Tempus Dominus looks slightly more "native Bootstrap" out of the box but drags in Popper and a bigger API surface for functionality we may not need yet.
